`agentaos.subscriptions` reads and manages subscriptions; it has no `create()`. A subscription starts when a buyer pays a [payment link](/sdk/pay-payment-links) created with `type: 'subscription'`. From then on AgentaOS, as merchant of record, bills the buyer every `billingInterval` by card or bank.

```typescript
const product = await agentaos.paymentLinks.create({
  amount: 29.99,
  currency: 'EUR',
  description: 'Pro',
  type: 'subscription',
  billingInterval: 'month',
});

// Logged-in user: create a checkout from the product's linkId
const checkout = await agentaos.checkouts.create({
  linkId: product.id,
  buyerEmail: user.email,
  buyerCountry: user.country,
  metadata: { customerId: user.id },
});
```

To copy a plan's link ID in the dashboard, open **Building this into your site?** on the plan's page and click **Copy ID**. When the buyer finishes, `checkout.session.completed` carries your `customerId` and the new `subscriptionId` in `data.metadata`. Store the `subscriptionId` on your user. Renewals do not carry your `customerId`, so match them by that `subscriptionId`. See [Receive webhooks in Express](/sdk/handle-webhooks) to verify the event.

See [Sell a subscription](/guides/sell-a-subscription).

## `subscriptions.list(params?)`

Mirrors the dashboard's Subscriptions list, scoped to the environment (test or live) your API key belongs to.

```typescript
const page = await agentaos.subscriptions.list({
  limit: 20,   // default 20, max 100
  offset: 0,
});
console.log(page.total, page.hasMore);
```

<ParamField query="limit" type="number" default="20">Max 100.</ParamField>
<ParamField query="offset" type="number" default="0" />
<ParamField query="discountCode" type="string">Only the subscribers who redeemed this code. The code as the buyer types it, not case-sensitive.</ParamField>

Returns `PaginatedList<Subscription>`.

### Read one subscription

There is no `retrieve(id)`. Store the subscription's `id` when the first `checkout.session.completed` arrives: it is `metadata.subscriptionId` on that event. To read the subscription later, page through `list()` and find it:

```typescript
import type { Subscription } from '@agentaos/pay';

async function findSubscription(subscriptionId: string): Promise<Subscription | undefined> {
  for (let offset = 0; ; offset += 100) {
    const page = await agentaos.subscriptions.list({ limit: 100, offset });
    const found = page.items.find((s) => s.id === subscriptionId);
    if (found || !page.hasMore) return found;
  }
}
```

[Paywall for logged-in users](/sdk/paywall-for-logged-in-users) shows the full pattern: store the id on your user, then read the subscription before a paid feature.

### Statuses

`SubscriptionStatus` is the card processor's status for the subscription. AgentaOS reads it on a schedule, so a change shows here after the next check. It has eight values. Webhook events never carry `incomplete` or `incomplete_expired`, because a subscription that never activated sends no event.

| Status | Meaning |
|---|---|
| `incomplete` | First payment attempt hasn't succeeded yet. |
| `incomplete_expired` | First payment never completed within the window; subscription never activated. |
| `trialing` | In a trial period, no charge yet. |
| `active` | Billing normally. |
| `past_due` | A renewal charge failed; the card processor is retrying. |
| `canceled` | Ended, no further charges. |
| `unpaid` | Renewal retries exhausted without a successful charge. |
| `paused` | Billing paused (e.g. a trial-without-payment-method configuration ending). |

## Free trials

A trial is a property of the product, not of the subscription: create the plan with `trialPeriodDays` (1 to 730). At checkout the buyer's card is saved with nothing due today, the subscription is created as `trialing`, and the first charge happens when the trial ends, after which it is `active`.

```typescript
const product = await agentaos.paymentLinks.create({
  amount: 29,
  currency: 'EUR',
  description: 'Pro, monthly',
  type: 'subscription',
  billingInterval: 'month',
  trialPeriodDays: 14,
});
```

What you observe:

- `checkout.session.completed` fires when the card is saved, with `amount: "0"`. Treat it as "trial started", not as money received. The wire body also has `trial: true` and `trial_end` (ISO 8601), which `verify()` returns as `trial` and `trialEnd`. The SDK type does not declare them yet: read them through a [wider type](/sdk/pay-webhooks#fields-the-type-does-not-declare-yet), or read `event.data.metadata.trial`, which is also `true`.
- `subscriptions.list()` shows `status: 'trialing'` and the plan's `unitAmountMinor`; `currentPeriodEnd` is the trial end while trialing.
- When the trial ends and the first charge succeeds, `checkout.session.completed` and `subscription.renewed` fire. See [Event order for subscriptions](/webhooks/events#event-order-for-subscriptions).
- Canceling during the trial stops it before any charge.

## `subscriptions.previewPlanChange(id, targetLinkId)`

Quote moving a subscription to another plan. Read-only: nothing is charged or scheduled. The target must be a different subscription product in the **same currency and billing interval**, and the subscription must be `active` or `trialing`; anything else is a `400`.

```typescript
const quote = await agentaos.subscriptions.previewPlanChange(sub.id, PRO_PLUS_LINK_ID);
// quote.direction      'upgrade' | 'downgrade' | 'revert'
// quote.dueTodayMinor  charged now (0 for a downgrade)
// quote.effectiveAt    upgrade: now; downgrade: the current period end
// quote.prorationDate  pass it to changePlan
```

<ResponseField name="direction" type="'upgrade' | 'downgrade' | 'revert'">`upgrade` when the new plan costs more per cycle, `downgrade` when it costs the same or less, `revert` when the target is the current plan while a downgrade is pending.</ResponseField>
<ResponseField name="currency" type="string" />
<ResponseField name="dueTodayMinor" type="number">Integer minor units charged now. Always `0` for a downgrade.</ResponseField>
<ResponseField name="dueTodayVatMinor" type="number" />
<ResponseField name="effectiveAt" type="string">ISO 8601. Upgrade: now. Downgrade: the current period end.</ResponseField>
<ResponseField name="nextInvoiceMinor" type="number">The next regular cycle invoice on the new plan, integer minor units.</ResponseField>
<ResponseField name="nextInvoiceVatMinor" type="number" />
<ResponseField name="nextInvoiceAt" type="string">ISO 8601.</ResponseField>
<ResponseField name="prorationDate" type="number">Unix seconds. Echo it in `changePlan` so the charge matches this quote.</ResponseField>

## `subscriptions.changePlan(id, { targetLinkId, prorationDate })`

Apply a quoted plan change. An **upgrade** charges the prorated difference on the saved card **now**; a **downgrade** charges nothing today and switches at the current period end. Idempotent on (subscription, target plan, `prorationDate`).

```typescript
const result = await agentaos.subscriptions.changePlan(sub.id, {
  targetLinkId: PRO_PLUS_LINK_ID,
  prorationDate: quote.prorationDate,
});

switch (result.direction) {
  case 'upgrade':
    console.log(result.status, result.unitAmountMinor); // charged now, e.g. 'active' 4900
    break;
  case 'downgrade':
    console.log(result.effectiveAt, result.unitAmountMinor); // when the cheaper plan starts
    break;
  case 'revert':
    console.log(result.unitAmountMinor); // the pending downgrade is canceled, the plan stays
    break;
}
```

Show the quote to the merchant (or the subscriber) before calling this: the upgrade charge is real money. The CLI does both steps in one command: `agenta subscriptions change-plan <id> --to <linkId>` (add `--dry-run` for the quote only).

**Canceling a scheduled downgrade.** Change the plan to the current plan again. The preview and the result come back with `direction: 'revert'`, nothing is charged, and `pendingPlanChange` is null afterwards. Targeting the plan that is already pending returns `400` ("already scheduled").

**Webhooks.** Every plan change fires `subscription.updated` on your account's webhook URL: when a downgrade is scheduled (`data.pendingPlan` is set), when it is reverted (`pendingPlan` back to null), when an upgrade is applied, and when the scheduled plan takes over at the period end. See [Events](/webhooks/events).

## `subscriptions.cancel(id)`

The cancellation always takes effect at the end of the current period: there is no immediate cancel. The subscriber keeps access until `currentPeriodEnd`. No refund. Calling it again is a no-op.

```typescript
await agentaos.subscriptions.cancel(sub.id);
```

### Response

<ResponseField name="status" type="SubscriptionStatus">Status after the cancellation call.</ResponseField>
<ResponseField name="currentPeriodEnd" type="string | null">ISO 8601.</ResponseField>
<ResponseField name="cancelAtPeriodEnd" type="boolean">Whether it's scheduled to cancel at period end vs. already canceled.</ResponseField>
<ResponseField name="effectiveCancelDate" type="string | null">ISO 8601 date the cancellation takes (or took) effect.</ResponseField>

```json
}
```

## `subscriptions.credit(id, { amountMinor, reason, idempotencyKey })`

Put credit on the subscriber's account. It comes off their next invoice and lowers what the card is charged. It is not a refund: no money goes back to the card. The client must be signed in as an owner or admin; an API key is refused with `403`.

```typescript
import { randomUUID } from 'node:crypto';

const credit = await agentaos.subscriptions.credit(sub.id, {
  amountMinor: 1000, // €10.00 in the plan's currency
  reason: 'Two days of downtime',
  idempotencyKey: randomUUID(),
});
credit.nextInvoiceDueAfterCreditMinor; // what the next invoice will charge
```

<ParamField body="amountMinor" type="number" required>Positive integer minor units. There is no currency field: the subscription's currency is used. At most the whole next invoice.</ParamField>
<ParamField body="reason" type="string" required>Why you give it. The subscriber never sees it.</ParamField>
<ParamField body="idempotencyKey" type="string" required>One key per credit you mean to give. Send the same key again when you retry after a timeout; a new key gives a second credit.</ParamField>

<ResponseField name="id" type="string">The ledger entry id.</ResponseField>
<ResponseField name="amountMinor" type="number" />
<ResponseField name="currency" type="string" />
<ResponseField name="reason" type="string" />
<ResponseField name="creditBalanceMinor" type="number">All unspent credit this buyer has with you now.</ResponseField>
<ResponseField name="nextInvoiceMinor" type="number">What the next invoice would have charged before this credit.</ResponseField>
<ResponseField name="nextInvoiceDueAfterCreditMinor" type="number">What it charges after it.</ResponseField>
<ResponseField name="nextInvoiceAt" type="string">ISO 8601.</ResponseField>
<ResponseField name="createdBy" type="string">The id of the person who gave it.</ResponseField>
<ResponseField name="createdAt" type="string">ISO 8601.</ResponseField>

The subscription must be `active` or `trialing`, not scheduled to cancel, and without a pending plan change; otherwise the call returns `400`. While the buyer has credit left, `previewPlanChange` and `changePlan` return `400` until the next invoice.

## `subscriptions.credits(id)`

The credits given on this subscription, newest first, and what is still unspent. Owner or admin only, like `credit`.

```typescript
const { items, balanceMinor } = await agentaos.subscriptions.credits(sub.id);
```

<ResponseField name="items" type="CreditEntry[]">`{ id, amountMinor, reason, createdBy, createdAt }` for each credit.</ResponseField>
<ResponseField name="balanceMinor" type="number">Unspent credit on the buyer, shared by every subscription they have with you.</ResponseField>
