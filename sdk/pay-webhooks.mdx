`webhooks.verify()` runs in your process and makes no network call. It checks the payload's HMAC-SHA256 signature against your webhook secret, rejects a stale or malformed signature, and returns the parsed event with camelCase keys. Set the destination URL and copy the signing secret in **Settings → Developers → Webhooks**, or set `webhookUrl` on a [checkout](/sdk/pay-checkouts) or link.

## `webhooks.verify(payload, signature, secret, toleranceSec?)`

```typescript
import express from 'express';
import { AgentaOS, WebhookVerificationError } from '@agentaos/pay';

const agentaos = new AgentaOS(process.env.AGENTAOS_API_KEY!);
const app = express();

// IMPORTANT: express.raw(), not express.json(). Verification needs the
// exact bytes that were signed. Parsing JSON first breaks the signature.
app.post('/webhooks', express.raw({ type: 'application/json' }), (req, res) => {
  let event;
  try {
    event = agentaos.webhooks.verify(
      req.body,                                       // raw body: string | Buffer
      req.headers['x-agentaos-signature'] as string,   // signature header
      process.env.AGENTAOS_WEBHOOK_SECRET!,            // whsec_... from the dashboard
    );
  } catch (err) {
    if (err instanceof WebhookVerificationError) {
      res.status(400).send('Invalid signature');
      return;
    }
    throw err;
  }

  switch (event.type) {
    case 'checkout.session.completed':
      console.log('Paid:', event.data.amount, event.data.currency);
      break;
    case 'send.completed':
      console.log('Sent:', event.data.amount, event.data.token);
      break;
    case 'send.failed':
      console.log('Send failed:', event.data.transactionId);
      break;
  }

  res.sendStatus(200);
});

app.listen(3000);
```

The samples on this page run on Express 4 and 5.

<ParamField body="payload" type="string | Buffer" required>
  The raw, unparsed request body. If it's a `Buffer`, it's decoded as UTF-8 before verifying.
</ParamField>

<ParamField body="signature" type="string" required>
  The `x-agentaos-signature` header value.
</ParamField>

<ParamField body="secret" type="string" required>
  Your webhook signing secret (`whsec_...`).
</ParamField>

<ParamField body="toleranceSec" type="number" default="300">
  Max age of the signature's timestamp, in seconds. A signature older than this throws `WebhookVerificationError`. A timestamp in the future throws too, by any amount: if your server's clock runs behind AgentaOS's, every event fails, so keep the clock synced (NTP).
</ParamField>

Returns a typed `WebhookEvent`. Throws [`WebhookVerificationError`](/sdk/pay-errors) on any failure.

### Signature format

The header is `t=<unix_timestamp>,v1=<hmac_hex>`. `verify()`:

1. Parses `t` and `v1` out of the header, throws if either is missing.
2. Checks `now - t` is between `0` and `toleranceSec` seconds, throws `Webhook signature expired` if not (this rejects both stale replays and clock-skewed future timestamps).
3. Recomputes `HMAC-SHA256(secret, "${t}.${payload}")` and compares it to `v1` with `crypto.timingSafeEqual` (constant-time, no early-exit on mismatch).
4. `JSON.parse`s the payload and deep-transforms it from snake_case to camelCase before returning it as a `WebhookEvent`.

Every failure at any step throws `WebhookVerificationError`. `verify()` never returns a partial or unverified event.

## `WebhookEvent`

A discriminated union on `type`. `switch`/narrow on it to get typed `data`.

<ResponseField name="type" type="'checkout.session.completed' | 'send.completed' | 'send.failed' | 'subscription.created' | 'subscription.renewed' | 'subscription.payment_failed' | 'subscription.updated' | 'subscription.canceled' | 'dispute.created' | 'dispute.closed' | 'account.updated' | 'webhook.test'" />
<ResponseField name="business" type="string">
  The id of the business the event happened in: your own, or one of the [businesses you manage](/connect/webhooks). Present on every event.
</ResponseField>

The wire JSON also carries an `id` for each event, but the `WebhookEvent` type does not declare it yet. Deduplicate on the keys in [Deduplication](/webhooks/events#deduplication).

Amounts follow the [money model](/api-reference/introduction#money-model): `amount` in `data` is a string, and `amountMinor` is an integer in minor units.

<Warning>
`verify()` camelCases every key, including the keys inside `metadata`. Use camelCase keys in metadata: a key like `user_id` comes back as `userId`.
</Warning>

### `checkout.session.completed`

Fires when a checkout is paid or a free trial starts. The full field list, with the wire names, is in [Events](/webhooks/events).

<ResponseField name="linkId" type="string">The payment link's public token from its `checkoutUrl`, not its `id`. `null` for a checkout created without a link, although the type says `string`.</ResponseField>
<ResponseField name="sessionId" type="string" />
<ResponseField name="amount" type="string">e.g. `"49.99"`.</ResponseField>
<ResponseField name="currency" type="string" />
<ResponseField name="txHash" type="string">On-chain settlement hash. `null` for a card or bank sale, although the type says `string`.</ResponseField>
<ResponseField name="payer" type="string">Payer wallet address. `null` for a card or bank sale, although the type says `string`.</ResponseField>
<ResponseField name="payerType" type="'human' | 'agent'" />
<ResponseField name="network" type="string">`card`, `bank_transfer`, or a CAIP-2 network ID for a stablecoin payment.</ResponseField>
<ResponseField name="livemode" type="boolean">`true` in live mode, `false` in test mode.</ResponseField>
<ResponseField name="metadata" type="object">The `metadata` you set on the checkout or payment link, with camelCase keys. `metadata.customerId` is your own id if you set one. On a renewal, `metadata` is AgentaOS's own: see [Event order for subscriptions](/webhooks/events#event-order-for-subscriptions).</ResponseField>

#### Fields the type does not declare yet

`verify()` also returns `rail`, `vendorReference`, `customerId`, `buyerEmail`, `buyerName` and `overpaidByCents` on every checkout event, and `trial` and `trialEnd` when a free trial starts. `customerId` is AgentaOS's id for the buyer, not your user id. `CheckoutCompletedData` does not declare these fields yet, so read them through a wider type:

```typescript
import type { CheckoutCompletedData } from '@agentaos/pay';

type CheckoutCompletedWire = CheckoutCompletedData & {
  customerId: string | null;
  buyerEmail: string | null;
  trial?: true;
  trialEnd?: string | null;
};

if (event.type === 'checkout.session.completed') {
  const data = event.data as CheckoutCompletedWire;
  if (data.trial) {
    console.log(`Trial started, first charge at ${data.trialEnd}`);
  }
}
```

`metadata.trial` is also `true` on a trial start, and needs no cast.

### `subscription.*`

All five `subscription.*` events carry the same `SubscriptionData`, delivered to your account's webhook URL. For when each one fires, and in what order, see [Event order for subscriptions](/webhooks/events#event-order-for-subscriptions).

<ResponseField name="id" type="string">The subscription's id, a UUID: the `id` that `subscriptions.list()` returns.</ResponseField>
<ResponseField name="status" type="string">The status after the change, one of the [subscription statuses](/sdk/pay-subscriptions#statuses). A subscription that never activated sends no event, so `incomplete` and `incomplete_expired` do not appear.</ResponseField>
<ResponseField name="planName" type="string | null">The plan name, from the backing payment link.</ResponseField>
<ResponseField name="currency" type="string" />
<ResponseField name="amountMinor" type="number">Per-cycle price in integer minor units. `1000` means `€10.00`.</ResponseField>
<ResponseField name="currentPeriodEnd" type="string | null">ISO 8601 timestamp, or `null` before the first cycle is set.</ResponseField>
<ResponseField name="cancelAtPeriodEnd" type="boolean">`true` once a cancellation is scheduled for period end.</ResponseField>
<ResponseField name="linkId" type="string">The current plan's payment link `id`, a UUID. Not the token in the checkout URL that `checkout.session.completed` sends as `linkId`.</ResponseField>
<ResponseField name="pendingPlan" type="object | null">
  Null unless a downgrade is scheduled. Then `{ linkId, planName, amountMinor, effectiveAt }`: the plan the subscription switches to at `effectiveAt`. `subscription.updated` fires when it is scheduled, reverted, and when it takes over.

### `account.updated`

A business's verification changed: its identity check landed, or we approved, held, resumed or rejected it, or asked it for changes. For a platform, `business` names the client it happened to. See [Platform webhooks](/connect/webhooks).

<ResponseField name="verification" type="'unverified' | 'in_review' | 'verified' | 'on_hold' | 'rejected'">Where the business's review stands, in the words the dashboard uses.</ResponseField>
<ResponseField name="changesRequested" type="boolean">We have asked the business something and are waiting on it.</ResponseField>
<ResponseField name="identityVerified" type="boolean">The identity check is done: its own, or its company's for another app of the same company.</ResponseField>
<ResponseField name="livemode" type="boolean">Always `true`: verification is about live money.</ResponseField>

<AccordionGroup>
  <Accordion title="Don't fulfill on the success page redirect">
    The customer can close the browser before the `successUrl` redirect lands. Fulfill orders from the webhook, which your server receives directly, not from the redirect.
  </Accordion>
  <Accordion title="Webhooks can be delivered more than once">
    Record a key per event, such as `event.data.sessionId` or `event.data.transactionId`, and skip an event you have already handled. The key for each event type is in [Deduplication](/webhooks/events#deduplication).
  </Accordion>
  <Accordion title="Poll as a fallback, not a replacement">
    If your endpoint is down, poll [`checkouts.retrieve()`](/sdk/pay-checkouts) for `status === 'completed'` as a backstop. Do not build your main flow on polling: it is slower, and every call counts against your [rate limit](/api-reference/introduction#rate-limits).
  </Accordion>
</AccordionGroup>
