---
title: "Subscribe Users in Your App"
description: "Each logged-in user gets their own checkout. Pass your user id, then turn the webhook into access, invoices, and cancel."
---

By the end of this guide a logged-in user can click Subscribe, pay on the hosted checkout, and your app will know who they are, whether they can use the product, what they were billed, and how to cancel.

This is for users who already have an account in **your** app. Unknown buyers who should just open a URL belong in [Sell a subscription](/guides/sell-a-subscription).

<Warning>
There is no `subscriptions.create()`. You do not mint a subscription with an API call. You create a **product** once, then for each user you create a **checkout** from that product's `linkId`. They pay. That payment is what creates the subscription.
</Warning>

## Before you start

- An AgentaOS account and a test API key (`sk_test_...`) from **Settings → Developers → API Keys**.
- `@agentaos/pay` on your server (`npm install @agentaos/pay`). Never put the key in the browser.
- A webhook URL AgentaOS can reach. Locally, use a tunnel. See [Handle webhooks](/guides/handle-webhooks).
- Your users already log in and have an email. You will send that email as `buyerEmail`.

Do this in **test mode** first. Test card at checkout: `4242 4242 4242 4242`, any future expiry, any CVC. Type it on the hosted page. Never send a card number to the API.

## The one id you will use

The dashboard calls this a **product**. The API creates it with `paymentLinks.create`. The id you pass around is `linkId`.

| Name | What it is | Where you see it |
|---|---|---|
| `linkId` | The product's UUID | Product page → **Copy link ID**, or `product.id` from `paymentLinks.create` |
| Buyer link | `/pay/…` URL | Product page → **Copy link**. For people who are not logged in. Do not send this to a logged-in user. |
| `sessionId` | One checkout attempt | `checkouts.create` → `checkout.sessionId` |

`linkId` is what `checkouts.create({ linkId })` wants. It is not the `/pay/…` slug.

## What you store

| You store | Where it comes from |
|---|---|
| `linkId` per product | Product page, or `paymentLinks.create` → `id` |
| Your own user id | Your database |
| AgentaOS `subscription.id` | After they pay (`metadata.subscriptionId` on the webhook, or a poll) |

Pass your user id as `metadata.customerId` on the checkout. It comes back on the webhook as `event.data.metadata.customerId`. It is **not** copied onto `subscriptions.list()`.

<Steps>
  <Step title="Create each product once">
    One product per price you sell. Copy `linkId` from **Catalog → Products**, or create it in code:

    ```typescript
    import { AgentaOS } from '@agentaos/pay';

    const agentaos = new AgentaOS(process.env.AGENTAOS_API_KEY!); // sk_test_...

    const product = await agentaos.paymentLinks.create({
      amount: 49,
      currency: 'EUR',
      description: 'Pro',
      type: 'subscription',
      billingInterval: 'month',
    });

    // Save product.id. That is the linkId.
    ```

    <Note>
    `amount: 49` means €49.00, not cents. Create this once per product, not once per user.
    </Note>
  </Step>

  <Step title="On login, see if they already subscribe">
    After the first payment, store `agentaosSubscriptionId` on your user. Then look that id up:

    ```typescript
    async function currentSubscription(user: { agentaosSubscriptionId: string | null }) {
      if (!user.agentaosSubscriptionId) return null;

      const page = await agentaos.subscriptions.list({ limit: 100 });
      const sub = page.items.find((s) => s.id === user.agentaosSubscriptionId);
      if (!sub) return null;

      const live = sub.status === 'active' || sub.status === 'trialing';
      return live ? sub : null;
    }
    ```

    If they have a live subscription, skip the paywall. If not, show products.

    `subscriptions.list` has no email filter. Page size max is 100. Store the subscription id. Do not scan by name.

    Fallback if you lost the id: find the item whose `customerEmail` equals the `buyerEmail` you sent.
  </Step>

  <Step title="They click Subscribe: create a checkout">
    Every click gets a **new** checkout, built from the product's `linkId`:

    ```typescript
    const checkout = await agentaos.checkouts.create({
      linkId: product.id,
      buyerEmail: user.email,
      buyerCountry: user.country, // ISO-2, e.g. 'DE'
      metadata: { customerId: user.id },
    });

    // Save checkout.sessionId on the user as pending.
    // Redirect them to checkout.checkoutUrl
    ```

    `linkId` is `product.id`. That is the only id you pass in.

    `buyerEmail` should be the same email as their profile. That is how AgentaOS attaches the customer.

    `buyerCountry` lets tax be calculated before they land on checkout.

    <Warning>
    Do not send a logged-in user the product `/pay/…` link. That page is for unknown buyers. A logged-in user gets the checkout you just created, so your `metadata.customerId` is on the session.
    </Warning>
  </Step>

  <Step title="Confirm they paid">
    Save `{ sessionId, customerId }` when you create the checkout. Then use either path.

    ### Webhook (preferred)

    When the first payment clears, AgentaOS POSTs `checkout.session.completed`. `event.data.metadata` is the checkout metadata: your keys, plus a few AgentaOS adds.

    ```typescript
    case 'checkout.session.completed': {
      const { sessionId, metadata } = event.data;
      const customerId = metadata?.customerId as string | undefined;
      const subscriptionId =
        typeof metadata?.subscriptionId === 'string' ? metadata.subscriptionId : null;

      if (!customerId || !subscriptionId) break;

      // Attach subscriptionId to your user (customerId).
      // Key idempotency on sessionId: the same event can be delivered twice.
      break;
    }
    ```

    What is in `metadata` on that first payment:

    | Key | Who put it there |
    |---|---|
    | `customerId` | You, on `checkouts.create` |
    | `subscriptionId` | AgentaOS, when the buyer starts the card form |
    | `payer`, `taxEvidence` | AgentaOS, for tax and the receipt |

    Later renewals also fire `checkout.session.completed`. Those do **not** include your `customerId`. Look up the user by the `subscription.id` you stored on the first payment.

    `subscriptions.list()` never includes this metadata.

    Verify the signature. Treat the handler as idempotent on `sessionId`. See [Handle webhooks](/guides/handle-webhooks).

    ### Poll

    If you do not have a public webhook URL yet:

    ```typescript
    const checkout = await agentaos.checkouts.retrieve(pendingSessionId);
    if (checkout.status === 'completed') {
      const subscriptionId = checkout.metadata?.subscriptionId;
      // Attach to your user.
    }
    ```

    Poll every few seconds until `completed`, `expired`, or `cancelled`.
  </Step>

  <Step title="Status, invoices, cancel">
    Use the stored `subscription.id`.

    ```typescript
    const page = await agentaos.subscriptions.list({ limit: 100 });
    const sub = page.items.find((s) => s.id === user.agentaosSubscriptionId);

    sub?.status; // active | trialing | past_due | canceled | ...
    sub?.cancelAtPeriodEnd;
    sub?.currentPeriodEnd;

    const invoices = await agentaos.subscriptions.invoices(sub.id);

    await agentaos.subscriptions.cancel(sub.id);
    ```

    Cancel does not refund. It stops the next renewal. The user keeps access until `currentPeriodEnd`. Immediate cancel is not supported. Calling cancel again is a no-op.

    PDF for one invoice: `agentaos.invoices.downloadPdf(invoice.id)` and `agentaos.invoices.getReceipt(invoice.id)`.
  </Step>
</Steps>

## Verify it worked

- Creating a checkout with a `linkId` and `metadata.customerId` redirects the user to `/checkout/…`, not `/pay/…`.
- Paying with the test card fires `checkout.session.completed`. `event.data.metadata.customerId` is the id you sent. `event.data.metadata.subscriptionId` is set.
- Your user row now has `agentaosSubscriptionId`. `subscriptions.list()` shows `status: 'active'` for that id.
- `subscriptions.list()` does **not** contain `customerId`. That only lives on the checkout and the webhook.
- Cancel sets `cancelAtPeriodEnd: true`. Access stays until `currentPeriodEnd`.
