`agenta status` is the command to run right after `agenta login`, and the one to reach for whenever something isn't working. It says who you are signed in as, where going live stands, and the next command to run.

```bash
agenta status
```

Alias: `agenta whoami`.

## What it checks

- **Account**: who you are signed in as, and for which organization.
- **Going live**: how many go-live steps are done, your business verification, the free Revenue & Pricing Audit, and your payout account.
- **Next step**: the one command that moves you forward, when there is one.

Test payments work as soon as you are signed in. Live payments wait on a verified business and a payout account.

## Usage

```bash
agenta status [--business <id>] [--json]
```

| Flag | Description |
|---|---|
| `--business <id>` | Show the status of a [business you manage](/cli/businesses). |
| `--json` | Output a single JSON object instead of the human-readable summary. |

## Example output

```bash Output
  Signed in as demo@founder.dev for Acme Freelance on https://api.agentaos.ai.

  Test payments work now. Live money waits on verification and a payout account.
  Go-live steps done: 1 of 3.
  Business verification: Not submitted.
  Free Revenue & Pricing Audit: Not requested.
  Payout account: not yet added.
  Next: start with the free audit (agenta audit request).
```

The three go-live steps are a first product or payment, a verified business and a payout account. The first line changes as you go:

| Where you are | First line |
|---|---|
| Not verified yet | Test payments work now. Live money waits on verification and a payout account. |
| Verified, no payout account | Test payments work now. Live money waits on a payout account. |
| Ready | You can take live payments. |

The `Next` line names the step that blocks you first:

| Where you are | `Next` points to |
|---|---|
| We asked for changes on your verification | `agenta verify resubmit` |
| Not verified, no audit requested | `agenta audit request` |
| Not verified, audit requested | `agenta verify submit` |
| Verified, no payout account | Adding a payout account in the dashboard |

In every other case there is no `Next` line, for example while your verification is in review.

<Tip>
`--json` also kicks in automatically whenever stdout isn't a terminal, so piping to `jq` or writing to a file gives you JSON without the flag: `agenta status | jq .goLive.next`.
</Tip>

## Response fields

| Field | Description |
|---|---|
| `account.authenticated` | Whether you have a valid session. |
| `account.email` | Account email, decoded from your session token. |
| `account.organization` | Your organization's name. |
| `account.orgId` | Your organization's id. |
| `account.paymentTools.ready` | Always `true` once you are signed in: test payments work. |
| `account.paymentTools.next` | A command to try a test payment. |
| `account.jwtExpiresAt` | ISO 8601 timestamp your session token expires at. |
| `account.jwtSecondsRemaining` | Seconds left before that expiry. |
| `account.configDir` | Where the CLI stores its local session config. |
| `goLive.canGoLive` | Whether you can take live payments. |
| `goLive.progress` | Go-live steps done, out of the total. |
| `goLive.verification.state` | `unverified`, `in_review`, `on_hold`, `verified` or `rejected`. |
| `goLive.verification.label` | The same state in words, including `Changes requested`. |
| `goLive.verification.changesRequested` | What we asked you to change. Empty when we asked for nothing. |
| `goLive.audit` | Where the free audit stands, with the report link once it exists. |
| `goLive.payouts.connected` | Whether you have added a payout account. |
| `goLive.milestones` | When you made your first product, test payment and live payment, and your live payment count. |
| `goLive.next` | The next `command` and `why`, or `null` when there is nothing to do. `command` is `null` when the step happens in the dashboard. |

## Not logged in

```json
{
  "account": {
    "authenticated": false,
    "reason": "not-logged-in",
    "next": "agenta login"
  }
}
```

The command prints this JSON with or without `--json`, and exits with code 0. `reason` is either `not-logged-in` or `session-expired`, so scripts can tell the two apart.
