# Guardian Wallet vs Fireblocks

Fireblocks is the industry standard for institutional MPC key management. Guardian Wallet brings the same security model to teams that don't have a $50k/yr budget.

Both use MPC threshold signing. Both split private keys into shares. The difference is who runs the infrastructure and what it costs.

---

## Quick Comparison

| | Guardian Wallet | Fireblocks |
|---|---|---|
| **Signing model** | 2-of-3 threshold ECDSA (CGGMP24) | MPC-CMP (proprietary) |
| **Key custody** | Self-hosted. You hold all shares. | Fireblocks holds shares on your behalf. |
| **Pricing** | Free and open source | $50k-$500k/yr (enterprise contracts) |
| **Setup time** | 5 minutes (Docker Compose) | Weeks (onboarding, compliance, contracts) |
| **Source code** | Open source (AGPL-3.0 server, Apache-2.0 SDK) | Proprietary |
| **Chain support** | Every EVM chain | 40+ chains (EVM, Bitcoin, Solana, Cosmos) |
| **Policy engine** | Spending limits, allowlists, rate limits, time windows | Comprehensive policy engine with approval flows |
| **Audit log** | Built-in, exportable | Built-in, SOC 2 compliant |
| **AI agent support** | Native SDK, CLI, MCP server | API-only |
| **Compliance** | Self-managed | SOC 2 Type II, ISO 27001 |
| **Support** | Community (GitHub) | Dedicated account manager |

## When to Choose Guardian

- **You're a developer or small team.** You don't need enterprise compliance or a dedicated account manager. You need signing that works.
- **You want to self-host.** Your keys live on your infra. No third party holds your shares.
- **You're building AI agents.** Guardian has a native TypeScript SDK, CLI, and MCP server designed for autonomous agent signing.
- **You can't justify $50k/yr.** Guardian is free. Clone the repo. Run it on a $5 VPS.
- **You want to read the source.** Every line of Guardian is open source. Audit the cryptography yourself.

---

## When to Choose Fireblocks

- **You need SOC 2 / ISO 27001 compliance.** Fireblocks is already certified. Self-hosting means managing your own compliance.
- **You're an institution managing billions.** Fireblocks has multi-layer approval workflows, gas station networks, and institutional-grade SLAs.
- **You need non-EVM chains today.** Fireblocks supports Bitcoin, Solana, Cosmos, and 40+ chains. Guardian currently covers EVM only (Bitcoin and Solana planned).
- **You need 24/7 enterprise support.** Fireblocks provides dedicated account managers and SLAs.

---

## The Security Model

Both Guardian and Fireblocks use MPC threshold signing. The core security property is the same: the full private key never exists as a single value.

**Guardian:** Three shares (Signer, Server, User). Any 2-of-3 can sign. You host all three. The signing protocol is CGGMP24, an open peer-reviewed algorithm implemented in Rust and compiled to WebAssembly. The implementation uses the [LFDT-Lockness/cggmp21](https://github.com/LFDT-Lockness/cggmp21) Rust crate.

**Fireblocks:** Proprietary MPC-CMP protocol. Fireblocks holds some shares, you hold others (depending on configuration). The implementation is closed-source.

## Migration

If you're already on Fireblocks and want to evaluate Guardian:

1. **Test in parallel.** Run Guardian on a testnet alongside your Fireblocks setup.
2. **Create a signer.** `gw init` takes 30 seconds.
3. **Compare the flow.** Sign a transaction with both. See the difference in setup complexity.
4. **Evaluate custody.** With Guardian, you hold all three shares. No vendor dependency.

<Tip>
Guardian doesn't require a migration from Fireblocks. Each signer gets a new Ethereum address via fresh key generation. You move funds to the new address when you're ready.
</Tip>
